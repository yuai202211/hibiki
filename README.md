# HIBIKI 日々記（ヒビキ）

日記・支払い・ルーティンを1つの画面で記録するアプリ。どの端末でも同じ記録が出て、続きが書ける。

- アプリ：https://yuai202211.github.io/hibiki/ （PWA。スマホは「ホーム画面に追加」）
- iPhone はホーム画面のアイコンから開く（Safari のタブで開くと保存領域とログインが別になり、しばらく使わないと端末の控えが消されることがある。記録の本体はクラウドにあるので、消えても次の起動で取り直す）
- 単一の HTML（`index.html`）＋ Service Worker（`sw.js`）＋ `manifest.webmanifest`
- データとログイン：Supabase（Auth・Postgres・Storage）。アプリに入っているのは公開前提のキーだけ
- 版：**c50.33**（`sw.js` の `VER` と画面の診断ラベルに出る）

## できること

- 下のボタン：トップ（日記）／支払い／メモ／ルーティン／**📊分析**／🎯一手
- 日記は「1行ずつ書く」がメイン。各行に時刻（任意）・📝詳細・**種類**（仕事・AI・読書など20種。＋で自分で足す・隠す・🕳️ムダ印）・**道具**（💻PC 📱スマホ など。＋で足せる）
- **移動**の記録でも1行ずつ書ける。乗り物に合わせた1タップ（車＝🔊音声で学ぶ・📞電話・🧠考え事、電車など＝🤖AI・💼仕事・📖読書…）。押すだけで移動中ずっと、時間を入れるとその分だけ
- **都道府県**：🗾 を押す → 日本のかたちのエリアを1回押す → その地方の県をくるくる回して選ぶ。新しい記録は直前の記録の県が入る（点線＝自動）
- **📊分析**：日・週・月・年で、何をした・🕳️ムダ（ムダ印の種類＋移動中に何もしなかった時間。徒歩は除く）・🚗移動の中身・🛠何を使って・🗾どこで

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（生成物。直接編集しない。生成の道具は非公開リポジトリ `hibiki-ai-context/tools/build.js` にある） |
| `sw.js` | オフライン起動用。更新したら `VER` を上げる |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | PWA の名前とアイコン |
| `dev/cloud-layer.js` | クラウド同期（ログイン・1項目1行の送受信・写真・引っ越し） |
| `dev/setup.sql` / `dev/setup-test.sql` / `dev/SETUP.md` | Supabase の表・関数・権限・写真置き場（`SETUP.md`＝作る手順） |
| `dev/PLAN.md` | クラウド化の計画書 |
| `dev/mock-supabase.js` / `dev/mock-test.js` | 手元テスト用の擬似サーバー（`node dev/mock-supabase.js`） |
| `dev/scan-public.js` | 公開前の検査（個人情報・鍵・埋め込みデータが無いこと） |

## 同期の考え方

- 記録は 1 項目 1 行（`items` 表）。各項目は `ts`（ミリ秒）を持ち、**新しい方が勝つ**。削除は `del:1` の墓石で、行は物理削除しない（削除権限そのものを付けていない）
- 端末は先に localStorage へ保存し、変わった項目だけを 1.5 秒後にまとめて送る。受信は `seq` の差分
- 写真は Storage の非公開バケット（`photos/<uid>/<id>`）。端末には取り寄せて控える

## 配信

`main` ブランチの `/` を GitHub Pages で配信。push 前に必ず `node dev/scan-public.js index.html` を通す。

### 日記の準備欄（c50.13）

日記に行き先・移動手段・出発時刻・最初の軽い作業を表示する。22時から翌日の準備、23時を締切として案内する。通知は既存の通知設定に従う。確定内容は既存の `prep` に保存・同期し、入力中の下書きは端末内に保存する。

見出しは「今日／明日、はじめにやる事」。当日の移動・場所の日記を保存すると、この予定のための記録か確認する。「いいえ」は次の記録時に再確認し、「はい」は `prep.fpLink` に実際の日記の参照を保存する。場所・時間・日記本文を上書きせず、作業完了とも分ける。紐づけはカードから取り消せる。予定の目的地を移動記録へ自動入力せず、到着時に実際の場所を選ぶ。

`dev/first-step.js` と `dev/first-step.css` が実装。非公開のビルダーではクラウド層の挿入前に `h=require(path.join(__dirname,'build-first-step.js'))(h);` を呼ぶ。`dev/build-first-step.js` は既存の挿入位置が変わるとエラーにし、機能の欠落を防ぐ。ビルド後は `node dev/test-first-step.js` で確認する。

### 記録の複数選択（c50.22）

仕事の各階層、端末、作業場所、連絡手段、事業の分類を複数選択できる。同じボタンを再度押すとその選択だけ外れる。既存の活動・AI・目的の複数選択も保存・再編集で保持する。各分類の時間はそれぞれ集計し、経過時間・移動時間は重複計上しない。

`dev/multi-select.js` と `dev/multi-select.css` が実装。非公開のビルダーは `build-first-step.js` の直後、クラウド層の挿入前に `h=require(path.join(__dirname,'build-multi-select.js'))(h);` を呼ぶ。`wm` は選択した仕事の階層、`wsx`・`hwx`・`bzx` は追加の選択肢を保存する。既存の `wc`・`k/kx`・`d/dd` と併記し、既存記録を一括書き換えない。検証は `node dev/test-multi-select.js`、`node dev/test-multi-analysis.js`、`node dev/test-work-buttons.js`。

### 熊谷手帳を読み返す習慣（c50.23）

起床後・最初の行動の前・就寝前に、各10分、自分で書いた中身をすべて読み返す。日記に3回分の進捗を表示し、開始・中断・再開を記録する。10分経過だけでは完了せず、手帳を閉じて覚えておきたい内容をひと言入力し、すべて読んだことを確認して読了にする。中断中と振り返りの入力時間は読む時間に含めない。アプリで実際の読書内容を検証するものではない。

開始・終了・読了状況は既存の `rlog` で保存・同期し、日記の時系列にも表示する。履歴から日時・読了を修正できる。習慣の日付は睡眠の終了・起床記録に合わせる。0時や朝5時を過ぎただけでは切り替えない。起床・最初の行動・就寝に案内を組み込み、既存通知設定に起床・就寝10分前・読書10分経過の案内を追加する。先に行動・就寝する場合は未完了のまま残す。iPhoneへの通知実配信は別途実機確認が必要。

実装は `dev/book-reading.js` と `dev/book-reading.css`。非公開ビルダーは `build-multi-select.js` の後に `h=require(path.join(__dirname,'build-book-reading.js'))(h);` を呼ぶ。検証は `node dev/test-book-reading.js`。


c50.24：振り返り文は入力確認にだけ使い、端末保存・クラウド同期・日記表示をしない。保存するのは時刻と振り返り済み・読了の状態のみ。旧版の振り返り文と専用下書きは、新版起動後に取り除く。既存の日記本文や他のルーティンは変更しない。

c50.25：運用開始日の2026年11月27日は就寝前の1回だけを対象とし、朝・行動前を未達に数えない。日付が変わってもその就寝前は初日の1回として扱い、次の起床記録から3回へ切り替える。


### 手帳のひと言・リセット（c50.26）

本人の最新指示で、ひと言は保存する運用に変更。「ほか」→「📖 手帳のひと言」で一覧・日付/言葉の絞り込み・再編集・「★ 支えになる言葉」を管理する。上部の検索にも「手帳のひと言」の種類を追加し、検索結果から編集できる。ひと言の結果で時間を加算せず、日記・分析を二重計上しない。

各読書回と専用一覧に「いつでもひと言を書く」を設け、計測前・途中・読了後に保存できる。コメント単独では読了にしない。読了時の入力も保存し、既存の同期対象 `rlog` の `brNote` を使用する（旧版の文章破棄処理から保護するため旧 `brReflection` と別のフィールド）。入力下書きは端末に保持する。ひと言単独は `brNoteOnly`、お気に入りは `brStar`。読書記録や日記を複製しない。旧版で保存しなかった文章を復元したとは扱わない。

「リセット」は確認後に対象回の計測・読了を0へ戻す。`brReset` にして読書集計から外し、保存済みの文章は残す。ほかの回・日記・予定を変更しない。日付またぎと初日の就寝前1回ルールも維持する。

「会議で振り返る」は表示中の条件に合う新しい40件までを、本人の記録と明記して画面に表示・コピーできる。自動送信はしない。会議チャットは開いているHIBIKIのこの画面を必要な期間だけ読み取れる。実装 `dev/book-notes.js` / `dev/book-notes.css` は `build-book-reading.js` から組み込む。

c50.27：日記の「自分」カテゴリーに「📖 夢手帳タイム」を追加。熊谷手帳を読み返す活動として、既存の選択・複数選択・検索・分析を利用する。

c50.28：「📖 夢手帳タイム」を日記入力の「⭐ よく押す」欄の先頭に固定表示。利用回数が0でも表示し、既存の固定ボタンの順序と設定は保持する。

### 日記一覧と選択ボタンの表示（c50.29）

滞在・移動・日跨ぎの活動をカードで区切り、各活動に開始／終了時刻・所要時間・種類・本文を順に表示する。未記入時刻は補完せず明示し、長文と細かな分類はその場で開ける。日記本文・時刻・集計値は変更しない。黄色の固定ボタンは上段、カテゴリーは区切り線の下段に配置する。

実装は dev/diary-layout.js と dev/diary-layout.css。ビルダーで build-book-reading.js の後に build-diary-layout.js を適用する。検証は node dev/test-diary-layout.js。

### 手帳タイムの日付切替（c50.30）

睡眠終了に加え、当日の最初の行動の開始・完了でも手帳の運用日を進める。睡眠の複数選択と、継続中の滞在内で終了した睡眠も検出する。日付変更だけでは進めず、未記録時は「起床済み・今日の3回へ」で明示して進められる。前日の読了・ひと言は維持し、睡眠時刻を推測して登録しない。明示切替は既存prepのbrWakeAtとして保存・同期する。検証: node dev/test-book-day.js、node dev/test-book-reading.js。

### 読書カードのボタン整理（c50.31）

本人の指示で、各読書カードの「いつでもひと言を書く」ボタンを撤去。読了時のひと言入力、保存済みコメント、専用一覧からの入力・編集は維持する。日記と手帳の画面分離・下部メニュー変更はデモ確認待ちで、この版には含めない。

### 手帳専用画面とナビゲーション（c50.32）

確認済みデモに沿い、1ページ目の右端を「手帳」、稼ぐを「ほか」（2ページ目）の先頭へ変更。既存の並び設定があってもこの2項目を配置し、他項目の相対順と保存データは維持する。

読書タイマーと自動読書履歴・ひと言を日記一覧から独立。「手帳」に「今日の10分」「ひと言・履歴」を設置。運用日と起床後／最初の行動の前／就寝前で履歴をまとめ、中断区間の読書時間を合算し、各区間の時刻修正とひと言の再編集を維持する。保存済みrlogの移行・複製・削除はせず、検索・お気に入り・会議用表示・同期も既存記録を使う。手動で付けた日記の「夢手帳タイム」と通常ルーティンは日記に残す。削除指示された単独のひと言追加ボタンは設けない。

実装はdev/book-page.js/cssとbuild-book-reading.js。検証: test-book-page.js、test-book-reading.js、test-book-day.js、test-first-step.js、test-diary-layout.js、公開前スキャン。合成データの360px/320px画面でナビ切替、コメント編集保存、時間修正、開始・中断を確認。

### 完了後の案内と履歴の絞り込み（c50.33）

「今日、はじめにやる事」は最初の行動が完了すると通常表示を終了し、未読了の手帳タイムを起床後→最初の行動の前→就寝前の順で1回ずつ表示する。計測中の回を優先し、10分経過だけでは進めずひと言の保存・読了後に次へ。3回読了で案内も終了。完了情報や準備内容は削除せず、明示編集と夜の翌日準備は維持する。就寝前は0時で切り替えず、従来の起床を基準にした運用日に従う。履歴の個別記録は日記一覧に混ぜない。

手帳の履歴は初期表示3回、追加表示も3回ずつ。常時見える日付入力・前日/翌日・今日ボタンで運用日ごとに絞り込む。日跨ぎの就寝前も元の運用日で探せる。詳細検索の実際に読んだ日付範囲・言葉・お気に入りと、編集・会議用表示を維持。検索結果から開く際は対象の運用日へ絞り込む。

検証: test-book-next.js、test-book-page.js、test-first-step.js、test-book-reading.js、test-book-day.js、test-diary-layout.js。合成データの実画面で準備完了→3回の読了→非表示、履歴3件→6件、日付切替、360px/320px表示を確認。

### 今日のToDo（c50.34）

下部「予定」を「ToDo」に変更。自由メモを同じ画面で書き、「この内容をToDoに反映」で入力順のカードへ変換する。「・大タイトル」の次の行から簡単な内容。内容なし・複数行・記号なしの1項目も受け付け、AIによる要約や推測はしない。空タイトルは全体を反映せず入力を保持する。反映前に件数を表示し、元の文章を保持、同じ反映操作の連打では重複しない。「── 今日、最低ここまで ──」はタスク数に含めない移動可能な区切りになる。

上ほど優先、先頭の未完了は青い「次はこれ」。右端のグリップを380ms長押しして並べ替え（上下キーも可）。今日の未完了と折りたたんだ「今日できたこと」のみを通常表示し、過去の未完了は自動繰越ししない。完了はタスク名付きの「はい／いいえ」で確認し、後から未完了に戻せる。タイトル・内容はその場で編集。既存の時刻・分類などは各カードの「⋯」、時間付きの予定は下部の折りたたみから利用できる。

検索はToDoの日付（開始・終了、今日／昨日／全期間）、タイトル・内容・反映元の文章、状態「すべて／完了／未完了」。複数語はAND、英字の大小・全角半角を正規化。過去・完了分を含み、検索結果からも編集・完了・取り消しが可能。検索結果は30件ずつ追加表示。

保存は既存の`todos`と`memos`を使用。`todos`には`tfDay`、`tfRank`、`tfSource`、`tfMemo`を追加。区切りはタイトルを持たない`tfDivider`行。`memos`の`tfDraft`行に入力全文、日付、反映済み状態と作成IDを保持し、通常メモ一覧からは除外。下書きは端末控えと既存同期で保持し、他端末の変更と競合した下書きは別IDへ分けて両方を残す。反映成功を端末保存後に判定し、失敗時は入力を残す。本文編集は競合検知し、日記・写真・既存属性の移行や一括変更を行わない。

実装は`dev/todo-flow.js/css`、`dev/build-todo-flow.js`。私用ビルダーで`build-diary-layout.js`の後に適用する。ルートの`todo-flow.css`は生成物で、HTMLとService WorkerのCOREから同じ版付きURLを参照する。CSSを更新する際は両方のURL版も更新する。
